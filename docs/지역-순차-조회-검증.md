# 지역 순차 조회 검증

확인일: 2026-10-24.

대시보드의 **지역 순차 조회 → 지역과 사이트 선택 → 시작**으로 실행한다. 확장 0.8.2와 변경된 대시보드 서버가 필요하다. 확장은 서버의 새 버전을 확인하면 자동으로 다시 불러온다. 이후 대시보드를 새로고침한다. 자동 갱신이 되지 않으면 `chrome://extensions`에서 확장을 새로고침한 뒤 대시보드도 새로고침한다.

전용 창의 탭 하나를 재사용한다. 중단, 이어하기, 미확인 다시 조회를 지원하며, 진행표와 미전송 응답을 확장 저장소에 보관한다. 서버가 응답과 매물 처리를 저장한 뒤 확인한 건수만 진행표에 반영한다. 동일 전송 묶음의 재전송은 중복 처리하지 않는다.

## 진행 상황과 로그

시작 버튼을 누르면 선택 항목 위에 현재 단계, 경과 시간, 탐색 횟수, 화면 응답 수신, 서버 저장 확인 건수가 나타난다. 처음에는 요청을 보냈다는 사실만 표시하며, 확장의 상태 응답을 받은 뒤 실제 단계를 표시한다. 준비 중에도 상태를 계속 읽고 저장소 변경을 바로 화면에 전달한다. **활동 로그**에는 시간순 이벤트를 최근 100개까지 남긴다. 작업별 상세 사유는 아래 진행표에서 확인한다.

마지막 상태 응답 시각과 작업 진행 신호 시각을 따로 확인한다. 연결이 끊기거나 진행 신호가 오래 갱신되지 않으면 현재 동작 중이라고 단정하지 않고 마지막으로 확인한 상태임을 알린다. 사이트 응답을 받았다는 로그와 서버 저장이 확인됐다는 로그도 구분한다.

동작 순서는 지역과 사이트 조합 준비 → 전용 탭에서 지역 URL 열기 → 확인한 목록 펼치기, 스크롤 → 페이지가 받은 응답 보관 → 서버 저장 확인 → 다음 작업이다. 사이트 전체를 직접 API로 검색하거나 전국 매물을 전수 수집하는 기능은 아니다.

로컬 서버의 `GET /api/browse/progress`에서도 최신 단계, 이벤트 코드, 집계, 수신 시각을 확인할 수 있다. 확장이 보내는 진단에는 지역 이름, 좌표, URL, 매물 본문, 자유 형식 오류를 넣지 않는다. 서버는 허용된 필드만 검증해 로컬 설정 DB에 최신 한 건을 보관한다. 진단 전송 실패가 실제 수집을 중단시키지는 않는다.

## 실제 사이트 화면 점검

개인 설정과 업무 장소를 사용하지 않고 공개 페이지를 별도 브라우저에서 열었다. 다음은 페이지와 DOM을 직접 확인한 결과이며, 확장을 설치한 크롬에서 서버 저장까지 전체 순회를 실행한 검증과는 구분한다.

| --- | --- | --- |
| [네이버 부동산](https://fin.land.naver.com/map) | 지도 묶음 버튼을 눌러 매물 목록이 열림을 확인. 기존 버튼 식별자와 매물 링크, 목록 스크롤 컨테이너가 실제 DOM과 일치 | 보이는 묶음을 열고 응답과 일치하는 목록을 탐색 |
| [다방](https://www.dabangapp.com/map/onetwo) | 좌표 URL로 지역 목록을 열고 스크롤 확인. 접근성 화면에는 일반 컨테이너로 보였지만 실제 카드는 LI이며, 제목과 가격으로 식별 가능 | 확인한 목록 스크롤 |
| [직방](https://www.zigbang.com/) | 원룸에서 공개 역을 검색해 역 번호가 포함된 URL과 목록을 확인. 스크롤 후 추가 카드가 나타남. 링크나 LI가 아닌 DIV 카드 때문에 기존 식별 방식이 놓치는 구간을 찾아 수정 | 받은 제목, 가격과 일치하는 직방 DIV 카드도 목록으로 인정 |

직방 보완은 `animatedComponent` DIV를 직방에서만 후보로 추가한다. 수신한 제목과 가격이 일치해야 하며, 카드 클릭이나 로그인, 찜, 연락 동작으로 확장하지 않는다. 테스트 데이터에는 실제 매물 문구나 번호를 복사하지 않았다.

## 자동 검증과 한계

합성 Chrome 저장소, 탭, DOM, 트랜잭션 메모리 DB로 다음을 검증한다. 운영 DB와 개인 설정은 테스트에서 불러오지 않는다.

- 여러 지역의 탭 재사용, 중단, 재개, 브라우저 재시작, 닫힌 창의 복구.
- 문서가 바뀐 뒤 늦게 온 응답과 다른 탭의 응답 분리. 미연결 전용 탭이 일반 수집으로 섞이지 않도록 차단.
- 서버 응답 유실 후 같은 배치 재전송, 저장 실패 롤백, 직방 신규 번호와 다방 초기 비교 기준의 배치 간 유지.
- 검증한 목록만 스크롤하고 가려진 버튼, 관련 없는 버튼은 누르지 않음. 로그인, 보안, 접근 제한 감지.
- 마지막 조작 후 응답 대기, 저장 확인 없는 페이지를 성공으로 표시하지 않음.
- 실제 백그라운드와 가져오는 스크립트를 함께 실행하여 최초 상태와 오류 응답 확인. 응답 없는 구버전 워커를 조회 준비 상태로 표시하지 않으며, 연결 오류 뒤 재확인으로 복구 가능.
- 준비 단계의 느린 서버 응답 중에도 상태를 읽을 수 있음. 늦은 상태 응답이 새 실행 요청이나 최신 진행 화면을 지우지 않음.
- 이벤트 기록 100개 제한, 수신과 저장 로그 분리, 익명 진단 검증, 서비스 워커 재시작 후 일정 복구와 확장 업데이트 시 안전한 중단.

실행 점검 중 이전 서버가 순차 조회 API에 404를 반환하는 문제는 서버 재시작으로 해결했다. 이후 대시보드의 시작 버튼이 비활성화된 채 확장 응답 없음 오류를 표시하는 증상이 확인됐다. 0.8.1에서는 실제 백그라운드 상태 응답을 받은 뒤 기능을 활성화하고, 연결 실패 시 확장, 대시보드 새로고침 안내와 재확인 버튼을 표시한다. 버전도 올려 같은 버전의 이전 워커가 남아 있는 경우 자동 갱신되도록 했다. 이 검증은 실제 크롬 순회가 매물을 저장했다는 확인을 대신하지 않는다.

0.8.2 진행 화면의 합성 브라우저 점검에서 시작 요청 자체를 막는 `DataCloneError`를 재현했다. 선택한 사이트 목록이 Vue의 반응형 배열이라 `window.postMessage`가 복제하지 못했고, 예외가 타임아웃 등록 전에 발생해 버튼이 계속 시작 중으로 남았다. 일반 배열로 복사해 전달하고, 전송 예외 시 대기 상태를 해제해 원인을 표시하도록 수정했다. 단위 테스트의 메시지 경계도 JSON 변환 대신 브라우저와 같은 구조화 복제로 바꾸어 재발을 확인한다.

사용자 크롬과 분리한 임시 브라우저에서 합성 지역만 사용해 시작 클릭, 진행 중, 오류, 중단, 좁은 화면을 점검했다. 브라우저 오류 0건과 외부 요청 0건을 확인했다. 실제 사용자 지역의 사이트 수집, 저장 검증은 별도로 확인해야 한다.

지역과 사이트 한 쌍은 최대 2분 또는 40번 조작하고 마지막 응답을 최대 15초 더 기다린다. 현재 지도, 거래 조건, 주택 유형 밖까지 전국의 모든 매물을 확인하지는 않는다. 역이나 단지 바로가기 정보가 없으면 직접 확인 필요로 남긴다. 서버 수신 건수와 매물 처리 건수는 다르며, 같은 매물 갱신도 처리 건수에 포함한다. 사이트 구조 변경이나 차단으로 진행하지 못한 부분은 진행표에서 확인해야 한다.
