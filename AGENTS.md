# Privacy

- Treat employer identity, employment relationships, and identifying workplace information as private. Do not infer or record them from indirect clues.
- Access to conversations, configuration, databases, screenshots, or history does not authorize publication. Do not put real organization identities, logos, internal URLs, domains, app IDs, email addresses, office locations, employee names, or identifying combinations into tracked files or external deliverables without explicit permission for the specific material, destination, and purpose.
- Apply this to source code, UI defaults, comments, documentation, fixtures, snapshots, logs, screenshots, filenames, paths, metadata, build artifacts, commit messages, pull requests, branches, tags, attachments, previews, analytics, and search or tool requests. Sanitize material before external transmission.
- Use unrelated synthetic examples by default, such as Example Company, Service A, and example.invalid. Changing a name while retaining recognizable content is insufficient.
- Use real workplace data only within an explicitly authorized private workflow. Keep it in ignored private configuration or an authorized database. Prefer generic labels and aggregate diagnostics.
- Inspect runtime exposure as well as Git contents. Public or example screens must not fall through to real configuration or data. Report risks without repeating private values and obtain authority before expanding scope or publishing.
- Before commits, pushes, pull requests, deployments, or artifact sharing, inspect the actual outgoing diff and generated content. Existing values or earlier generic approval do not authorize exposure. Pause an external action if permission is uncertain.
- Do not restore sanitized information through stale history, branches, tags, stashes, backups, fixtures, documents, or memories. Do not publish anonymization mappings.
- Persist these preferences rather than actual employer identities. Do not claim that local instructions automatically synchronize to another computer, account, or assistant.

# Writing

- Do not add AI authorship credits or generation notices to commit messages or pull request titles and descriptions, including AI Co-Authored-By trailers.
- Do not use the middle dot character U+00B7 in replies, newly written UI copy, or documents. Use natural wording, commas, or separate lines.
- Do not join list-item labels and explanations with dashes or horizontal bars, including U+3161, U+2014, and U+2013. Use a colon or a complete sentence.
